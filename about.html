03 — About the evaluator

Designing for access is designing for people.

This page explains the perspective behind the evaluation and the accessibility decisions made in the report website itself.

01 — Perspective

A note from the evaluator

I am an HCI student interested in inclusive and accessible design. This evaluation gave me an opportunity to look beyond whether a task is visually straightforward and ask whether it is equally understandable and operable through different ways of interacting.

I used Quora's question-creation flow as a practical case study. The testing also reminded me that using assistive technology requires learning: my unfamiliarity with VoiceOver made parts of the experience difficult to interpret. I have kept that reflection separate from claims about WCAG conformance.

A REFLECTION

Accessibility testing is not about assuming what a person can or cannot do. It is about checking whether the interface provides clear, flexible ways to perceive information and complete a task.

02 — This website

How this report promotes accessibility

The report website is also a small design exercise. Its structure and controls are intended to make the content easier to navigate and read.

Aa

Readable typography

Poppins is used for body copy and Montserrat for headings, with a clear hierarchy, generous line length and responsive sizing.

↹

Keyboard-first structure

A skip link, semantic landmarks, native links and buttons, visible focus styles and logical document order support keyboard navigation.

▧

Descriptive image alternatives

Evidence screenshots have alt text describing the relevant screen and interface elements. Decorative marks are hidden from assistive technology.

A+

Reading preferences

Readers can increase or decrease paragraph text size, add more line and paragraph spacing, and toggle a bionic-style emphasis treatment.

H

Meaningful hierarchy

Pages use one main heading, descriptive section headings, labelled navigation and semantic lists for the task flow and references.

◉

Careful interaction feedback

Copy-code buttons provide a polite status announcement, and reading preference changes are announced without moving focus.

03 — Try the controls

Make the page work for your reading preference

The reading controls are available in the toolbar at the top of every page. They adjust paragraph text, spacing and visual word emphasis.

About bionic-style reading

This optional display treatment visually emphasises the beginning of words. It is an experimental reading preference, not a proven accessibility accommodation. The underlying text remains available to screen readers as normal text. Turn it off if it makes reading harder.

About line and paragraph breaks

The spacing control increases line height and the space between paragraphs. It does not rewrite the content or insert arbitrary line breaks, so the document structure remains consistent for assistive technology.

04 — Limitations

What this website does not claim

  • This report website has not been certified as WCAG conformant. It should itself be tested with keyboard navigation, screen readers, zoom and automated tools.
  • The Quora findings are preliminary. Some are direct observations; others require inspection of Quora's actual HTML and accessibility tree.
  • Illustrative code snippets explain accessible patterns. They are not Quora source code.
  • External Google Fonts require an internet connection. System font fallbacks are provided if the fonts cannot load.
